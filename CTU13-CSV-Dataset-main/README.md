# CTU-13 Botnet Dataset (CSV Flow Extract)

## 🎯 Purpose
The CTU-13 dataset provides **real-world, captured botnet Command & Control (C2) traffic** mixed with normal background network activity. Unlike many modern datasets that rely on synthetic or scripted attacks, CTU-13 features actual malware executions captured in a live university network. 

In our multimodal LSTM pipeline, this dataset serves as the primary source for the **Flow Branch**, providing the genuine, sustained beaconing and C2 communication patterns that synthetic datasets fail to replicate accurately.

---

## 📊 Key Characteristics
- **Origin**: Captured at CTU University, Czech Republic, in 2011.
- **Environment**: Real network environment infected with live botnet malware, not a controlled lab simulation.
- **Composition**: Consists of 13 distinct scenarios (captures). Each scenario features a different specific malware/botnet sample performing various actions, mixed with normal and background traffic.
- **Processing**: The raw PCAP files have already been processed using the **CICFlowMeter** tool, converting packet-level data into standardized flow-level CSVs. This saves us from having to write complex PCAP parsing logic.

---

## 📁 Core Files & Features

### 1. `CTU13_Attack_Traffic.csv` – *The Botnet Signal*
Contains all network flows originating from or destined to the known infected botnet IPs. 
- **Label**: `Botnet`
- **MITRE Mapping**: Maps directly to **Command & Control** (beaconing) and **Execution**.

### 2. `CTU13_Normal_Traffic.csv` – *The Baseline*
Contains all network flows from non-infected IPs, representing legitimate user activity and background network noise.
- **Label**: `Normal` / `Background`
- **MITRE Mapping**: Maps to **Benign**.

### 3. Feature Set (~80 CICFlowMeter Features)
Because this was generated by CICFlowMeter, it shares the exact same feature schema as CIC-IDS2017. Key features include:
- **Timing**: `Duration`, `Timestamp`
- **Volume**: `Total Fwd Packets`, `Total Backward Packets`, `Total Length of Fwd Packets`
- **Rates**: `Flow Bytes/s`, `Flow Packets/s`, `Down/Up Ratio`
- **Flags & Headers**: `FIN Flag Count`, `SYN Flag Count`, `PSH Flag Count`, etc.

---

## ⚠️ Important Handling Notes for Our Pipeline
1. **Feature Selection**: The raw CSVs contain ~80 features. For our Flow Branch LSTM, we will extract a canonical subset of ~20 highly predictive numerical features to reduce dimensionality and noise.
2. **Data Cleaning (Crucial)**: CICFlowMeter generates `Infinity` and `NaN` values in rate-based features (like `Flow Bytes/s`) when a flow's `Duration` is exactly 0. These must be imputed (e.g., replaced with 0 or median) before scaling.
3. **Label Harmonization**: The native labels are just "Botnet" and "Normal". We will map `Botnet` to our unified MITRE target space (specifically the C2/Execution class).
4. **Chronological Splitting**: The data is already sorted by timestamp in the CSVs. We must split it strictly chronologically (e.g., 70% Train / 15% Val / 15% Test) to prevent future-state leakage. Do not shuffle randomly.
